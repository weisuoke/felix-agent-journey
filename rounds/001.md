## 本轮目标

七天内做出一个能独立解释、验证业务结果、处理失败的 Agent 项目。重点是原生 loop、工具、检索、状态、安全与评估，不追求框架数量或复杂 UI。

本轮开始前用知识清单自测，记录基线：哪些能解释、哪些能实现、哪些已有验证证据。这里不预设已经掌握。

## 主项目：带审批的知识库工单 Agent

流程：用户描述问题 → 检索知识库 → 查询已有工单 → 给出有引用的建议 → 必要时拟定新工单 → 用户确认后写入数据库。

使用真实文档与本地 SQLite；不需要接付费工单平台，但写入和查询必须真实发生，不能用固定返回值假装完成。演示使用隔离数据，不接生产系统。

最小工具集：

- `search_docs`：查询知识库，返回内容与来源。
- `get_ticket`：读取已有工单。
- `create_ticket`：写入工单；程序强制校验审批、参数与幂等键。

第一天即定义验收用例，后续每天补充失败案例；第六天集中运行和比较，不把评估留到最后才设计。

## 七天安排

### Day 1：LLM API 与原生 Agent Loop

- [ ] 定义任务成功标准，准备少量文档和隔离工单数据。
- [ ] 用原生模型 SDK 实现循环，先接入 `search_docs`、`get_ticket` 两个只读工具。
- [ ] 正确保存消息、关联调用 ID、回填工具结果；处理正常结束和预算耗尽。
- [ ] 设置步数、时间、token 预算，记录模型与参数。

产出：可运行 CLI、一次真实多轮工具调用记录、初始验收任务。

自测：不看教程能否画出并解释 loop？模型在调用工具，还是在生成调用请求？

### Day 2：工具契约与失败处理

- [ ] 改善工具名称、描述与参数 schema，在执行前做业务校验。
- [ ] 覆盖未知工具、非法参数、工具异常、超时与限流。
- [ ] 区分可重试与不可重试错误；独立只读工具才考虑并行。
- [ ] 验证失败后不误报成功，预算耗尽后不会继续循环。

产出：工具执行层、失败场景记录、可解释的错误分类。

自测：schema 合法是否就能执行？哪些错误可以交给模型修正，哪些必须直接阻止？

### Day 3：RAG 与上下文管理

- [ ] 实现文档切分、索引、检索和来源返回，先使用简单可运行方案。
- [ ] 理解 BM25、向量检索、混合检索和 reranking；按实际失败决定是否加入。
- [ ] 回答带可核对引用；证据不足时拒答或追问。
- [ ] 控制工具结果长度和对话上下文；保留目标、约束与未完成动作。

产出：正常检索、无证据、相似但不相关文档三类案例及诊断。

自测：错误发生在检索、排序、上下文选择，还是生成阶段？

### Day 4：状态、审批与恢复

- [ ] 选一个框架，默认 LangGraph；理解 state、node、edge、checkpoint、interrupt。
- [ ] 接入 `create_ticket`，将拟定与实际写入分开，未经用户确认不写入。
- [ ] 持久化执行状态，演示暂停、确认、恢复；保留原生 loop 的学习证据。
- [ ] 明确审批绑定的任务和拟定内容，内容变化后不能沿用旧审批。

产出：一次真实暂停恢复记录、审批后落库及查询结果。

自测：框架解决了什么？审批和权限为什么必须由程序检查？

### Day 5：安全、幂等与 MCP

- [ ] 通过幂等键和数据库约束防止重复创建工单。
- [ ] 验证重复请求、写入后响应丢失／恢复执行不会重复落库。
- [ ] 给工具设置最小权限，使用含恶意指令的文档验证不能越权。
- [ ] 做最小 MCP 接入：通过 MCP 暴露一个只读工具，并从客户端发现、调用。

产出：重复提交、未审批、恶意文档三个场景的业务状态证据；MCP 调用记录。

自测：MCP 与 function calling 如何配合？为什么写操作超时不能盲目重试？

### Day 6：Evals、可观测性与优化

- [ ] 整理约 20–30 个任务，覆盖正常、追问、无证据、失败、重复提交与安全场景。
- [ ] 每次 trial 从隔离初始状态开始；关键任务重复运行，记录波动。
- [ ] 用代码检查落库、重复记录和权限；开放式回答使用明确 rubric 并人工抽查。
- [ ] 保存 trace、工具耗时、token、成本与任务总耗时；小样本延迟不作生产结论。
- [ ] 只改一个变量，对比修改前后；保留失败类型，不只汇报平均分。

产出：实际评估报告，标明模型、配置、样本数、重复次数、成功标准和未覆盖范围。

自测：改善是真实变化还是随机波动？是否牺牲了安全、成本或延迟？

### Day 7：面试演练与本轮复盘

- [ ] 无 AI 辅助写一个 Agent Loop，解释工具调用和失败路径。
- [ ] 做一次系统设计：目标 → 工具权限 → 状态恢复 → 检索 → 评估 → 成本延迟。
- [ ] 做 5 分钟项目演示，包含成功、失败和一次优化前后对比。
- [ ] 用知识清单脱稿回答；记录答不清楚的问题与实际反馈。
- [ ] 完成本轮复盘，再决定是否追加下一轮 7 天。

产出：可展示项目、实际评估结果、项目叙述、下一轮候选缺口。

## 本轮验收

- [ ] 能独立实现和解释原生多轮 Agent Loop。
- [ ] 答案有可核对引用，无证据不编造。
- [ ] 缺必要字段时追问，不猜测后写入。
- [ ] 未审批不创建工单，审批在程序边界强制执行。
- [ ] 重复请求／恢复执行不产生重复工单。
- [ ] 工具失败不声称成功，预算耗尽明确终止。
- [ ] 文档里的恶意指令不能触发越权工具调用。
- [ ] 能检查工具调用、错误、耗时、token 与最终数据库状态。
- [ ] 有实际运行的评估与改动前后对比，不虚构准确率。
- [ ] 能讲清架构取舍、失败案例和未覆盖范围。
